# Security Policy

Quiverstone helps teams reach AWS accounts they don't own, so we take security reports seriously.

## Reporting a vulnerability

**Please do not open a public issue, discussion, or pull request for security problems.**

- **In a repository:** use GitHub's private reporting — open the repository's **Security** tab and choose
  **Report a vulnerability**.
- **For the Quiverstone platform or website:** reach us through
  [quiverstone.io/contact](https://www.quiverstone.io/contact/) and ask for a security contact, or see
  [quiverstone.io/security](https://www.quiverstone.io/security/).

Please include:

- What is affected (repository, template, or platform area) and the version or commit
- Steps to reproduce, or a proof of concept
- The impact you believe it has

Never include real AWS credentials, account IDs, External IDs, or customer data in a report.

## What to expect

| Step | Target |
| --- | --- |
| Acknowledge your report | 3 business days |
| Initial assessment and severity | 10 business days |
| Fix or mitigation plan | Shared with you once confirmed |

We'll keep you updated, credit you in the advisory if you'd like, and ask that you give us a reasonable
window to fix the issue before disclosing it publicly.

## Supported versions

Unless a repository says otherwise, only the latest release (or the default branch, if there are no
releases) receives security fixes.
